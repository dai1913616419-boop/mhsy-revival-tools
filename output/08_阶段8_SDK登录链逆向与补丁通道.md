## 2. SDK 登录链（已完整逆向）

日志里的 `U3DSDK` = **`MobileGameDemo.AndroidSdkConnector`**，位于 `Client.dll`。
`Client.dll` 在热更清单里（`Client/GameRes/Resources/Client.bytes.bytes`），
**因此改 DLL 原则上不需要改 APK、不需要签名。**

```
启动流程（实测日志）
  AndroidSdkConnector.Init   → callSdkApi("GetSdkInfo") → g_SdkName = "360..."（来自 Java SDK）
  AndroidSdkConnector.StartLogin
      ldfld ignoreLogin → 若 true 则 ret（跳过一切 SDK 调用）
      callSdkApi("IsInitFinished") → callSdkApi("OpenLogin")   ← 卡在这里
  登录成功后回调 CBUserLoginSuccess(string) → 写 LoginSystem 的账号/密码/token
  LoginSystem.AccountSubmit → CCMsgAccountEnter（msgid 101）→ 连游戏服
```

### 三个可用绕过点

| 方案 | 机制 | 改动量 |
|---|---|---|
| **A. IL patch `StartLogin`** | 方法开头 `ldfld ignoreLogin` 改成 `ldc.i4.1`（+nop 填充），使 `brfalse` 不跳转直接 `ret` | **6 字节**，方法体长度不变，无需改 PE 头 |
| **B. IL patch 成直接回调** | 把 `StartLogin` 改成直接 `call CBUserLoginSuccess("uid#=#equal#=#..#&#and#&#pwd#=#equal#=#..")`，注入假账号后走游戏自己的登录 | 需解决新字符串入 `#US` 堆的问题 |
| **C. Frida hook** | 模拟器有 root，hook `StartLogin` 后直接调 `CBUserLoginSuccess` 传任意字符串 | 运行时注入，最灵活，但要装 frida-server |

`CBUserLoginSuccess` 的字符串格式（从 `SplitStringToDic` 确认）：
项分隔 `#&#and#&#`，键值分隔 `#=#equal#=#`。

## 3. 意外收获：`GameData/game.cfg` 是官方配置开关

`LoginSystem::Open` 读取 **`GameData/game.cfg`**（按 `=` 分割的 key=value），可配置项包括：

```
choice_server_login     → mChoiceServerLogin（是否显示选服登录）
show_nonsdk_pwd_dlg     → mShow_nonsdk_pwd_dlg（显示非 SDK 密码框）
ServerListUrl           → 服务器列表地址
<SdkName>_ServerListUrl → 按渠道区分的服务器列表地址
```

**`ServerListUrl` 完全由这个文件决定** —— 意味着游戏服地址可以由我们下发的文件指定，
这正是我们需要的控制点。

已写好 `server/patches/4.2.0.2/GameData/game.cfg`：
```
ServerListUrl=http://game.360joy.com.cn/Other/serverlist.txt
show_nonsdk_pwd_dlg=true
choice_server_login=true
```

**实测结果**：用 adb push 放到 persistentDataPath 后，游戏**仍然**走 `callSdkApi OpenLogin`。
结论：`game.cfg` 只控制登录框的显示形态，**不能阻止 SDK 登录调用**。绕过仍需走 A/B/C。

## 4. 卡点：热更补丁通道不下载文件

对照实验（清单里同时放两个文件）：

```
<file fpath="Client/GameRes/Resources/Resource.txt.bytes" ... />   ← 原清单里本就有的文件
<file fpath="GameData/game.cfg" ... />                              ← 新增路径的文件
```

服务器日志：
```
GET /Android_90/UpdateRoot/Version/Version.bytes                          → 200
GET /Android_90/UpdateRoot/IncrementPack/4.2.0.2/.../MD5File.txt.bytes    → 200
（之后没有任何资源请求）
```

**两个文件都没下载**，所以不是"新路径被过滤"的问题，而是流程在
`CompareMD5File` → `downLoadAssets` 之间就没往下走。

已排除的可能：
- `parseMD5File` 不做路径变换，key 就是 `fpath` 原样
- `CompareMD5File` 逻辑正常（本地没有 → 加入下载列表）
- 不是域名/网络问题（Version 和 MD5File 都成功）

待查：`<UpdateResource>c__Iterator1`（主迭代器）中下载阶段的触发条件。

## 5. 过程中的两个操作坑（已记入 README 待补）

1. **重启服务器前必须 `taskkill //F //IM python.exe`** —— 否则端口被旧进程占用，
   新进程静默启动失败，继续下发旧版本号（曾因此误判"配置没生效"）。
2. **bind mount 的 hosts 会失效** —— 启动游戏前重跑 `setup_mumu_hosts.py`。
