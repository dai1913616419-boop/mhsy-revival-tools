### 2. 副本刷怪机制查明（重要认知修正）
- **怪物是客户端本地刷的**，不走 105/106 实体下发：刷怪脚本在
  `GameData/RegionLogic/<关卡id>_gk.xml`（共 369 个关卡全在 APK 内）。
- 以 3010 为例：出生点 BornBos(24.09, 199.60, 52.64)，走到 Trigger2(Z≈78, 半径10)
  才刷新怪物 `3010_PTBS0179`（模型 SAO_Monster12，**资源在 APK 内**，carved/MD5File.txt 确认）。
- **阶段13副本没怪是正常现象**——角色没走到触发点，不是缺资源。

### 3. 副本角色物理激活（修复"无法移动"）
- 根因：服务端只发一次 103 BornPos=(0,0,0)（登录时）。进副本后客户端把角色放在
  (0,0,0) → 每帧 `Touch floor failed!!!`（logcat 实锤）→ 物理失效、不刷怪、坐标停止上报。
- 修复：服务端实现 **C→S 104 LevelLoadFinish{region_res_id}** 处理——
  解析关卡号（注意 protobuf tag 字节），从 `RegionLogic/<id>_gk.xml` 读 BornBos 回发 103。
- 效果：进副本后角色站上正确出生点，**坐标上报恢复**，Touch floor 失败归零。

### 4. 副本结算链打通 ✅
- 倒计时归零 → 客户端发 **C→S 302 ResultFB{result=2失败}** →
  服务端回 **S→C 1001 {result=2, starCount=0}** →
  **"挑战失败"完整结算窗弹出**（数据统计/技能升级/英雄进阶提示齐全，截图为证）。
- handler 链：OnMsgResultFBRet(rva 0x26fa00) → 事件111 → 结算 UI。

### Tier C：无法 100% 还原，需要你抉择 ⚠

**C1. 热更新资源缺失（当前最大的硬墙）**
- 原版客户端启动后从官方 CDN（已死）下载场景 AB、UI 图集等。
  APK 内置资源不含全部 UI 图集（如结算窗的 Atlas）与部分关卡场景。
- 可选方案：
  - **C1-a 寻找历史资源包**：搜旧版完整 APK/资源缓存（若该游戏有过其他渠道包/PC 乞丐版），
    找到则完美还原。我需要你提供或允许我花时间网上搜证。
  - **C1-b 程序化占位**：写工具生成纯色/线框占位图集注入，UI 能用但难看。
  - **C1-c IL 补丁跳过缺图**：SetIcon 找不到图集时不抛异常（类似阶段14 patch 思路），UI 缺图标但流程通。
- **推荐：先 C1-c（成本低、立刻解锁结算/回城），再并行 C1-a 搜资源。**

**C2. 服务端权威战斗（JJC 实时战/跨服战）**
- 这类战斗的命中/伤害由原服务端模拟，客户端只是播放器。原服务端逻辑已不可得。
- 方案：自写简化战斗模拟器（用 MonsterProperty/WuJiang 表的攻防血公式），
  生成战报包给客户端播放。数值可能与原版有偏差，但玩法成立。

**C3. 多人玩法（实时组队/公会战对抗）**
- 单机沙箱内无真实其他玩家。方案：AI 假人+服务端模拟，或放弃对抗只留 PVE。
