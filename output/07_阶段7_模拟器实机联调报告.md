## 3. 拦路虎与解法

### 3.1 remount 失败 → bind mount 解决 ✅

MuMu 12 是 `user` 版（debuggable=0），`/system` 所在块设备物理只读（`blockdev --getro`=1），
remount 必败。改用 **bind mount**：

```sh
su 0 mount -o bind /data/local/tmp/hosts.mhsy /system/etc/hosts
```

不需要写块设备，挂载点层面覆盖，实测生效。**局限：模拟器重启后失效，需重跑脚本。**
已固化进 `server/setup_mumu_hosts.py`（自动找 adb → su 0 → bind mount → 模拟器内 curl 验证）。

### 3.2 服务器多渠道支持 ✅

`update_server.py` 重写路由为正则匹配 `/(Android[^/]*)/UpdateRoot/...`，
按渠道下发不同版本号（`server_versions` 配置）：

- `Android` → `4.0.0.2`（3 段应答）
- `Android_90` → `4.2.0.1`（6 段应答，含 ForceUpdateAddress 字段）

版本号与客户端内置一致 ⇒ CheckVersion 返回 3 ⇒ 跳过更新直接用内置资源。
另补了 `/Other/Android_90/QF.xml`、`Notice.txt` 两个此前 404 的文件（客户端有请求它们）。

## 4. 配置表问题的新进展

- 从 4.2.0.1 的 `Client.dll`（已 carve：`work/apk/Client_4201.dll`）解析出 **117 个 `GameData/` 配置表路径**
  （导出到 `work/apk/gamedata_paths.json`），例如：
  `GameData/WuJiangBaseAttri.ini`、`GameData/RegionList.txt`、`GameData/game.cfg` 等。
- 确认 UC 4.0.0.2 清单（5760 条）与 4.2.0.1 清单（832 条）都**不含**任何 GameData 条目；
  两个 APK 内也搜不到表数据（UTF-8/UTF-16 均无）。
- ⇒ 配置表数据彻底缺失是硬事实。两种可能：登录后由游戏服下发，或客户端从持久化目录读
  （`/data/.../files/MHSY/ABs/`，当前为空）。**等绕过 SDK 登录连上我们的游戏服后，
  观察它到底要什么，再决定造表策略。**
- 顺带发现 4.2.0.1 Client.dll 里残留开发者内网调试地址：`http://192.168.0.157/UpLoad/UnityUpload.php`。

## 5. 下一步（阶段 8 目标）：绕过渠道 SDK 登录

游戏调用链：`U3DSDK StartLogin → callSdkApi OpenLogin`（C# 调 Java SDK）。
SDK 登录成功后游戏拿 token 走自己的 `CCMsgAccountEnter`（账号密码制）连游戏服。

候选方案（按侵入度排序）：
1. **热更下发补丁 DLL**：确认 U3DSDK 所在 DLL 是否在热更清单内（`Client.bytes`）；
   若在，改 DLL 里的登录入口直接回调"登录成功"，零改包。
2. **Frida hook**：模拟器有 root，装 frida-server，hook SDK 登录回调注入假 token。
3. **改包签名**： Assembly-CSharp.dll 层面 patch（工具链已备好：`patch_apk_version.py` + `sign_apk.py`）。

同时要确认游戏服（TCP 网关）的地址来源 —— 之前分析 `CMsgServerData` 由服务端下发 IP/Port，
但登录服的第一跳地址从哪来还需要从抓包/日志确认。
