## 二、程序集提取（绕开 Unity 解析器的做法）

没有使用 apktool / UnityPy / JDK。直接做 **PE carving**：

1. 在 `assets/bin/Data/*` 的 Unity 序列化文件中搜索 `MZ` + `PE\0\0`
2. 读 PE 可选头 → Section Table → 取 `PointerToRawData + SizeOfRawData` 的最大值求总长
3. 用 `BSJB`（.NET 元数据签名）校验切片有效性

一次命中 4 个程序集：

| 文件 | 大小 | 说明 |
|---|---|---|
| `Client.dll` | 3.14 MB | 客户端逻辑，命名空间 `MobileGameDemo`（1583 个类型） |
| `Msg.dll` | 566 KB | **全部 protobuf 消息契约**（483 个类型） |
| `protobuf-net.dll` | 78 KB | Marc Gravell protobuf-net |
| `ProtobufSerializer.dll` | 405 KB | 序列化封装 |

产物：`work/carved/*.dll`

## 三、消息协议（已完整导出）

用 `dnfile`（纯 Python）解析 CLI 元数据：

- `[ProtoContract]` × 482 → **421 个消息类型**
- `[ProtoMember(n)]` × 1413 → **1413 个字段**
- 注意：`ProtoMember` 挂在**自动属性**（PropertyRow）而非字段上，归属需走 `PropertyMap` 表解析

字段类型分布：int32 707、string 267、bool 91，另有 `List<T>` 与枚举。
命名空间：`NetProto`

产物：`output/01_消息清单.md` / `.json`

### 登录链路（已确认）

```
CMsgCenterCheckAccount(4)     → CMsgCenterCheckAccountRet(5)      // 中心服校验账号
CCMsgCheckLogin(3)             → CCMsgCheckLogin_Ret(5)            // 登录
CMsgRequestServerType(1)       → CMsgServerData(9)                 // ← 拿到 IP + Port
CCMsgRequestCreateRole(2)      → CCMsgRequestCreateRole_Ret(1)     // 创建角色
CCMsgReConnect / _Ret                                              // 断线重连（存在！）
```

`CMsgServerData` 关键字段：

```
[3] int32   ServerID
[5] string  IP      ← 游戏服地址由服务端下发
[6] int32   Port
[9] int32   Sessionid
```

`CCMsgAccountEnter` 含 `account / password / token / sdkNo / deviceId`
→ **登录是账号密码制**，UC 渠道只是在外层套 token。对做本地免鉴权非常有利。

**这条对"手机在外网连接家里服务端"是决定性利好**：只需重定向中心服入口，
游戏服地址由我们自己的服务端想返回什么就返回什么。

## 五、热更新机制（我们需要模拟的部分）

```
assets/bin/Data/7bcccccbb…  →  http://game.360joy.com.cn/Android/UpdateRoot/Version|IncrementPack|4.0.0.2
```

流程（据 `Assembly-CSharp.dll` 的 `GameResUpdate` 推断）：

1. 取 `Version.bytes` 得到版本号
2. 与本地 `MD5File.txt` 比对
3. 下载 `IncrementPack`（**LZMA 压缩**，代码里有 `LZAMCompressed` / `DecompressSuccess`）
4. 解包覆盖到 `/StreamingAssets/` 与持久化目录

`MD5File.txt`（已提取，850 KB，5760 条）**只覆盖 `Client/**.bytes` 美术资产**，
不含任何 `GameData` 或 `.lua`。

**重要利好**：`Client/GameRes/Resources/{Client,Msg,protobuf-net,ProtobufSerializer}.bytes.bytes`
**本身也在热更清单里** —— 意味着我们可以通过自建更新服下发**补丁后的 DLL**，
**完全不需要改动 APK 本身**（也就不用重新签名、不用 root）。

## 六、⚠️ 阻塞项：运行时资源缺失

### 缺失内容

- **94 个 `GameData/*.txt` 配置表**（装备、武将、VIP、任务、副本、公会、商城……）
- **`main.lua`** 及 Lua 脚本（`ClientCore.dll` 内嵌 Lua VM，逻辑在 Lua 侧）
- **`GameData/game.cfg`**（含中心服 IP/端口）

### 验证方式（三重交叉确认，无遗漏）

1. 全包 ASCII + UTF-16 双通道字符串扫描 → 无 `GameData/*` 内容、无 Lua 源码
2. `MD5File.txt`（5760 条完整热更清单）解析 → 0 条 GameData，0 条 Lua

   **没有 LZMA / UnityFS / UnityWeb 隐藏压缩包**可藏内容

## 七、下一步建议（需你决策）

见「可行路径」讨论。核心矛盾：**协议层已经 100% 打通，但内容层（配置表 + Lua）缺失。**

可选路径：

| 方案 | 说明 | 风险 |
|---|---|---|
| **A. 获取更高版本完整包** | 外网存在 v4.0.0.37 / v4.2.0.1 / v4.4.1.1（160~178 MB）。较新的包可能把 GameData/Lua 打进了基础包。取到后直接**移植资源**或改用新客户端 | 第三方站点可信度需自行判断；版本差异可能导致协议不兼容（但可重新导出 Msg.dll 验证） |
| **B. 同源换皮包** | 《剑舞者们》是同引擎换皮作，目录结构高度相似 | 游戏内容不同，配置表语义对不上，仅能参考结构 |
| **C. 自造配置表 + Lua** | 按 94 个文件名与用途自行编写 | 工作量以月计，且是"重做一个游戏"，非复原 |
| **D. 只做协议层** | 到此为止，交付协议文档 + 服务端骨架，不做内容复原 | 无法真正进游戏 |

**我推荐 A**：先验证一个较高版本包是否内嵌这些资源。这是成本最低、
且唯一有可能真正复原的路径。
