# 阶段 10 报告 —— 登录进服里程碑打通

> 日期：2026-09-30
> 状态：**登录链路已打通（客户端接受账号并开始加载游戏场景）**

---

## 1. 本阶段目标

上阶段结束时：客户端能连本地 TCP 9001、完成 INIT 握手、发 601 `CCMsgReConnect`，
但无论回 101 还是 901，客户端都在应答后立刻断连/崩溃。

本阶段目标：搞清楚断连根因，打通「登录 → 进入游戏」。

---

## 2. 根因一：帧 CRC 必须正确（最关键发现）

之前"客户端不校验 CRC"的结论是**错的**（当时看错了偏移）。

`ClientSession::OnDataReceived`（rva=0x291cec）反汇编确认：

```
expected = BitConverter.ToUInt32(buffer, offset + 6)        ; 帧 +6 = crc 字段
actual   = Crc32.GetStreamCRC32(buffer, offset+12, len-12)  ; body 的 CRC32
actual != expected  ->  触发 Error 事件 + Close()
```

CRC32 实现（`Crc32` 类，查表在 FieldRVA，表头 `0x77073096 …`）：
**就是标准 zlib CRC32**（初值 0xFFFFFFFF，末尾异或， reflected 多项式 0xEDB88320）。

> 这解释了此前所有"玄学"现象：空 body 时 CRC32(空)=0，我们恰好发的也是 0，
> 所以"碰巧"能过；一旦 body 非空（`0801`、完整 901、101）全部立刻断连。
> 之前 0801 INIT 导致 mono abort，也是 CRC 不匹配 + 异常冒泡到原生线程所致。

**修复**：`make_frame()` 里 `crc = zlib.crc32(body) & 0xFFFFFFFF`。

修复后立即生效：完整 901 应答被正常接收，连接稳定，Lua 打出
`NET_CCMsgReConnect_Ret never process by lua module`。

## 3. 根因二：INIT 应答的 SerialNumber 决定登录分支

`NetworkManager::OnInitNetWork`（rva=0x241ac0）还原：

```
IsCenterServer = (INIT应答.SerialNumber == 0)
PostEvent(652, "IsCenterServer" = IsCenterServer)
if (this.ᜃ)  发 601 CCMsgReConnect{account=LoginSystem.UserAccount, sdkNo=get_SdkId()}
```

`LoginSystem::ᜀ`（rva=0x1a73e4，事件 652/655/656/657/658 处理器）：

```
case 652:
    if (IsCenterServer == true)   -> 发 msgid 10  CCMsgCheckLogin（走中心服连接）
    if (IsCenterServer == false)  -> AccountSubmit()
                                     -> 发 msgid 101 CCMsgAccountEnter
                                        {account, password, token, sdkNo, deviceId}
```

`AccountSubmit`（rva=0x1a7278）有前置门：`if (this.ᜀ == 0) return;`
该标志在选服提交路径 `LoginSystem::ᜀ`（rva=0x1a7020）末尾被置 1，
即**用户点「进入游戏」后**才允许提交。

### 结论

| INIT 应答 SerialNumber | 客户端行为 |
|---|---|
| 0（我们此前一直这么发） | IsCenterServer=true → 试图走中心服 → 卡死/重连 |
| **非 0（如 1）** | IsCenterServer=false → `AccountSubmit()` → 发 101 |

同时：601 `CCMsgReConnect` 只是重连通道，登录主链路是 **101**，与 901 无关。

服务端改为：INIT 回 `CMSG_INIT_TOClient{SerialNumber=1}`，收到 101 回
`CSMsgAccountEnterRet{dynID=1, svrCurTime=…}`。

服务端日志（`server/logs/game_server.log`）：

```
<< 收到 msgid=1(INIT握手)      总长=12 body=0 字节

     field 4 varint = 1002                       ← sdkNo（360 渠道）
```

## 6. 关键消息号速查（本阶段确认）

| msgid | 方向 | 类型 | 说明 |
|---|---|---|---|
| 1 | C→S / S→C | `CMSG_INIT_TOClient` | 握手；应答 `SerialNumber==0` → 中心服分支 |
| 2 | S→C | `CMsgErrorCode` | 服务器踢人/错误 → 客户端事件 658 → 重新点亮提交按钮 |

| 101 | C→S | `CCMsgAccountEnter` | 登录：account/password/token/sdkNo/deviceId |
| 101 | S→C | `CSMsgAccountEnterRet` | dynID / alreadyNewUserGuideFB / debug / mainRoleIndex / svrCurTime / isEnableHundredTower… |
| 601 | C→S | `CCMsgReConnect` | 重连通道 |
| 901 | S→C | `CCMsgReConnect_Ret` | result / player / svrCurTime |
| 102/5401/5402 | C→S | ?（泛型约束型，类型未解出） | 大厅阶段 fire-and-forget 请求 |
