# 06 — 热更新协议逆向与本地更新服设计

> 阶段目标：搞清楚客户端启动时到底向服务器要什么、怎么判断要不要更新、资源从哪下载，
> 并据此搭出一个可以冒充官方更新服的本地服务。
> 方法：静态提取 `Assembly-CSharp.dll` → `dnfile` 解析元数据 → `dncil` 反汇编 `GameResUpdate` 命名空间全部方法。
> 结论：**热更新通道完全可用**，且支持"只下发少量补丁文件"，不需要重建整个资源包。

---

## 1. 关键代码位置

| 项 | 值 |
|---|---|
| 承载程序集 | `assets/bin/Data/Managed/Assembly-CSharp.dll`（97 KB，Unity 层启动器） |
| 命名空间 | `GameResUpdate` |
| 主类 | `GameResUpdateMng`（40 个方法） |
| 入口 | `Launcher.Start` → `GameResUpdateMng.Start` → `UpdateResource` → `SubUpdateResource` |
| 版本数据类 | `VersionFile`、`MD5File`、`EUpdateFlag` |
| 本地版本文件 | `assets/bin/Data/7bcccccbb6d31a741b30b3f77d8d946c`（Unity TextAsset，路径 `Version.bytes`） |

`Client.dll` 里**没有**更新逻辑——它只在资源下载完成后才被加载。这印证了之前的判断：
DLL（`Client.bytes` / `Msg.bytes` / `protobuf-net.bytes` / `ProtobufSerializer.bytes`）是通过热更下发的，
**改 DLL 不需要改 APK**。

## 2. 客户端内置的版本配置

`Version.bytes` 内容（从 `assets/bin/Data/7bcccccbb6d31a741b30b3f77d8d946c` 直接读出）：

```
http://game.360joy.com.cn/Android/UpdateRoot/Version
|
http://game.360joy.com.cn/Android/UpdateRoot/IncrementPack
|
4.0.0.2
```

`GameResUpdateMng.parseVersionFile` 用 `|`(0x7C) 切成 3 段，存进 `VersionFile`：

| 字段 | 内容 |
|---|---|
| `mServerVersionFileIP` | `http://game.360joy.com.cn/Android/UpdateRoot/Version` |
| `mServerIncrementPackIP` | `http://game.360joy.com.cn/Android/UpdateRoot/IncrementPack` |
| `mVersion` | `4.0.0.2` |

序列化布局（`server/patch_apk_version.py` 已实现自动改写）：

```
文件 offset  0 : m_MetadataSize   (大端)
文件 offset  4 : m_FileSize       (大端, 4236)
文件 offset 12 : m_DataOffset     (大端, 4096)
文件 offset 20 : "4.6.3f1\0"
文件 offset 44 : ObjectInfo { m_ObjectID=1, byteStart=0, byteSize=140, typeID=49 }  <- 小端
                             └ byteSize 落在 offset 52
offset 4096 : 07 00 00 00 "Version\0"          <- key
offset 4108 : 77 00 00 00                       <- value 长度（小端，0x77 = 119）
offset 4112 : "http://game.360joy.com.cn/..."   <- value 正文（119 字节）
```

⚠️ 坑：Unity serialized file **只有头部是大端，metadata（对象表）是小端**。
改 value 长度时必须同步改三处：value 长度（小端）、offset 52 的 byteSize（小端）、
offset 4 的 m_FileSize（大端）。脚本已自动定位并校验。

小技巧：域名换成 `192.168.0.12:8080`（15 字符）时替换后总长度**恰好不变**（delta=0），
三处长度字段都不用动，是风险最低的改法。

## 3. 完整启动流程（已反汇编确认）

```
Launcher.Start
  └─ GameResUpdateMng.Start
       └─ UpdateResource                       (协程 Iterator1)
            ├─ ClearState
            ├─ DecompressAssetBundleFileFromApk   ← 首次启动：把 APK 内 AssetBundle 解压到本地
            └─ SubUpdateResource                  (协程 Iterator2)
                 ├─ 读本地 Version.bytes → parseVersionFile → mLocalVersionFile
                 ├─ 客户端的两个 IP 字段 ← 本地 Version.bytes（注意：不是服务器的！）
                 ├─ url = mServerVersionFileIP + "/Version.bytes"
                 ├─ WWW 下载该 url
                 └─ 回调 <>m__1:
                      ├─ parseVersionFile(下载内容) → mServerVersionFile
                      ├─ this.mVersion = mServerVersionFile.mVersion   ← 只覆盖版本号
                      ├─ mflag = CheckVersion(本地, 服务器)
                      ├─ mflag == 3 → mComplete = 1，跳过更新，直接进游戏
                      └─ mflag == 1 → 走下面
                           ├─ 读本地 Client/GameRes/Resources/MD5File.txt.bytes → parseMD5File
                           ├─ url = get_ServerRootPahtCareVersion() + "/Client/GameRes/Resources/MD5File.txt.bytes"
                           ├─ 下载服务器 MD5File → parseMD5File → mServerPathMD5
                           ├─ CompareMD5File(服务器清单, 本地清单) → mUpdateAssets
                           └─ downLoadAssets: 逐个 WWW 下载 mUpdateAssets
                                └─ 全部完成后 ReplaceLocalRes 写回 MD5File / Version.bytes
                                   mComplete = 1
```

### 3.1 URL 拼接规则（三条，全部硬编码可推导）

```python
# 1) 版本文件
VERSION_URL = mServerVersionFileIP + "/Version.bytes"
#   http://game.360joy.com.cn/Android/UpdateRoot/Version/Version.bytes

# 2) 资源根（get_ServerRootPahtCareVersion）
RES_ROOT = mServerIncrementPackIP + "/" + mServerVersionFile.mVersion
#   http://game.360joy.com.cn/Android/UpdateRoot/IncrementPack/4.0.0.3

# 3) 单个资源
FILE_URL = RES_ROOT + "/" + fpath
#   .../IncrementPack/4.0.0.3/Client/GameRes/Resources/xxx.bytes

# MD5 清单固定路径
MD5_URL = RES_ROOT + "/Client/GameRes/Resources/MD5File.txt.bytes"
```

⚠️ **重要**：`mServerVersionFileIP` / `mServerIncrementPackIP` 这两个**域名**在整个流程中
只来自 APK 内置的 `Version.bytes`，服务器下发的版本文件里即便写了别的地址，客户端也不用
（`<>m__1` 只取第三段 `mVersion`）。
→ **重定向必须靠 hosts 或改包，不能靠服务器下发新地址。**

### 3.2 版本比较语义（`CheckVersion`）

按 `.` 切成 4 段逐段比较（本地 vs 服务器）：

| 返回值 | 含义 | 客户端行为 |
|---|---|---|
| `1` | 服务器版本更高 | 走完整更新流程 |
| `2` | 服务器版本更低（异常） | 不更新 |
| `3` | 版本相同 | `mComplete=1`，**跳过更新直接进游戏** |

### 3.3 MD5 清单格式

APK 内置的 `MD5File.txt`（5760 条）是 XML：

```xml
<Version>
  <file fpath="Client/GameRes/Media/.../Add.shader.bytes" size="6648" md5="818BC881AD9BDBF43E3C596DCD6E4F60" />
  ...
</Version>
```

`parseMD5File` 读入两个字典：`mPathMD5[fpath] = md5`、`mSize[fpath] = size`。
md5 为**大写** 32 位十六进制。

### 3.4 差量下载逻辑（`CompareMD5File`）—— 本阶段最有用的发现

```
mUpdateAssets = []
for fpath in 服务器清单:
    if fpath 不在本地清单:      mUpdateAssets += fpath
    elif md5 与本地不同:        mUpdateAssets += fpath
    else:                       跳过
```

**结论：服务器清单不必包含全部 5760 个文件。**
只要列出我们要替换的那几个（给对 md5 和 size），客户端就只会下载这几个，
其余文件继续用 APK 内置的。补丁包可以很小。

## 4. 两种运行模式

### 模式 A：跳过更新（推荐先跑这个）

`server_version = 4.0.0.2`（与客户端内置一致）→ `CheckVersion` 返回 3 →
客户端不联网拉资源，直接用 APK 内置资源启动。

- 优点：零资源准备工作，最快看到登录界面
- 用途：验证启动链路、观察 UC SDK 行为、抓登录网关请求

### 模式 B：下发补丁

`server_version = 4.0.0.3`（更高）→ 客户端拉取我们的 `MD5File.txt.bytes`，
按差量下载 `patches/4.0.0.3/` 下的文件。

- 用途：替换 `Client.bytes` / 配置表 / 后续任何资源，全程不改 APK
- 注意：更新成功后客户端会把新版本写回本地，下次启动本地版本即 4.0.0.3

## 5. 重定向方案（必须二选一）

客户端只会访问 `game.360joy.com.cn`，而该域名已失效。

### 方案 1：改 hosts（推荐先试，不动 APK）

```bash
adb root
adb remount
adb shell "echo '192.168.0.12 game.360joy.com.cn' >> /system/etc/hosts"
adb reboot
```

- 模拟器（雷电 / MuMu / 夜神）一般都支持 `adb root`
- 本机局域网 IP：`192.168.0.12`（如变动需在 `update_config.json` 同步）

### 方案 2：改 APK 副本的 Version.bytes

`server/patch_apk_version.py` 会自动：
1. 复制 APK → `*.patched.apk`
2. 替换 `assets/bin/Data/7bcccccbb6d31a741b30b3f77d8d946c` 内的域名串
3. 同步修正 value 长度（offset 4108）、对象 byteSize（offset 36）、m_FileSize（offset 4）
4. 重新打包（保持原压缩方式）

缺点：APK 需要重签名（Unity 4.6 时代是 v1 签名，模拟器一般不校验）。
原始 APK 只读，产出为副本。

## 7. 下一步建议

1. **先跑模式 A**：起服务器 + 模拟器改 hosts + 装 APK，确认客户端能跳过更新进入登录界面，
   同时看 `logs/update_server.log` 里客户端还请求了什么（用于侦察 SDK / 网关）。
2. 观察卡点：UC SDK 初始化是否会联网失败并阻塞（这是目前最大的未知风险）。
3. 之后切模式 B：用 `make_patch.py` 下发第一批补丁（配置表 / `Client.bytes`）。
4. 再往后才是真正的 TCP 网关 / 游戏服（`CMsgServerData` 下发 IP:Port，重定向只需改那一处）。

## 8. 风险登记

| 风险 | 影响 | 预案 |
|---|---|---|
| UC SDK 强制联网校验，失败即退出 | 客户端进不了登录界面 | 观察后决定：打桩 SDK / 换 `CCMsgAccountEnter` 直连 / Frida hook |
| 模拟器 `adb remount` 失败 | hosts 改不了 | 改用方案 2 改包，或用 ProxyDroid 全局代理 |
| 80 端口被占用 | 服务器起不来 | 换 8080，同步改 hosts（hosts 不带端口）→ 需改包或端口转发 |
| Android 9+ 禁明文 HTTP | 请求失败 | 选 Android 5.1/7.1 的模拟器实例 |

### ⚠️ Android 15 是本项目的主要兼容性风险

| 风险点 | 说明 |
|---|---|
| 32 位 ABI | APK 只有 `lib/armeabi-v7a`，Android 15 把 32 位支持改为可选，能否安装未知 |
| 16KB page size | Android 15 可开启，老的 `libmono.so` / `libunity.so` 可能加载失败 |
| `/system` 只读 | 高版本用动态分区，`adb remount` 可能失败 → hosts 改不了 |
| 明文 HTTP | 该 APK targetSdk 很低（Unity 4.6 时代），默认允许明文，问题不大 |

**建议**：优先在 MuMu 多开器里新建一个 **Android 6 或 Android 7** 实例
（会自动下载对应的 `nx_device` 镜像）。2015 年的 Unity 4.6 游戏在低版本上兼容性最好。

### 已准备的三个脚本

| 脚本 | 作用 |
|---|---|
| `setup_mumu_hosts.py` | 一键：找 adb → 连端口（自动试 16384/7555/16400/…）→ root → remount → 写 hosts → 装 APK，并打印 ABI/系统版本 |
| `patch_apk_version.py` | 改 APK 副本里的更新服域名（已离线验证） |
| `sign_apk.py` | 纯 Python 的 v1 签名，本机无 JDK 也能用（依赖已装的 `cryptography 50.0.1`） |

签名已用小 zip 验证：MANIFEST.MF / CERT.SF 格式正确，
CERT.RSA 可被 `pkcs7.load_der_pkcs7_certificates()` 正常解析，算法 `sha256WithRSAEncryption`。

### 兜底路径

```
启动 MuMu → setup_mumu_hosts.py
   ├─ remount 成功 → 改 hosts → 起 update_server.py → 跑游戏
   └─ remount 失败 → patch_apk_version.py + sign_apk.py → adb install → 跑游戏
```
