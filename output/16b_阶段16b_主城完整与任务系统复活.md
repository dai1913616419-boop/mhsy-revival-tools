## 2. 头号根因：登录时过早推送任务

### 现象
冷启动 → 登录 → 界面卡在 **"英雄们正在擦拭武器…"** 加载条不再前进；`logcat` 每帧刷
`NullReferenceException at MainPlayer.DailyTaskPromptState → DaTingMainUISystem.Open`。

### 定位过程
1. `disasm_full.py` 反汇编 `DaTingMainUISystem.Open`（rva 0x1208ec），发现它依次调用：
   ```
   ldsfld  fld:ᜀ                        // MainPlayer 静态单例
   callvirt MainPlayer::OnceTaskPromptState   // rva 0x60e48
   callvirt MainPlayer::DailyTaskPromptState  // rva 0x60dbc
   callvirt MainPlayer::TeQuanFuLiPromptState // rva 0x60ed4
   ```
2. `DailyTaskPromptState` 方法体首两条即 `ldarg.0; ldfld mCompleteMember; ldfld mAllDailyTaskInfo`。
3. 关键在**时机**：`OnFirstUpdateOnceTask`（1103 handler，rva 0x2719e0）同样以
   `ldsfld fld:ᜀ` 开头——若此时 **MainPlayer 单例尚未创建**，即 NRE。
   MainPlayer 单例由 **102 handler**（`OnQuestFirstEnterRegionRet` rva 0x26edb0）里的
   `UnitManager::CreateUnit` + `stsfld fld:ᜀ` 创建。
4. 对比历史成功案例（18:57 日志）：**登录应答里没有 1103/1101**，主城正常进入。

### 结论
> 服务端在**登录应答（102 之后）立即推送 1103/1101**，客户端 `OnFirstUpdateOnceTask`
> 访问尚不存在的 MainPlayer 单例抛 NRE，中断主城 UI 的打开流程 → 加载条永不消失。
> 这是**阶段16b 引入的回归**，也是此前"卡加载"的唯一原因。

### 修复
`server/game_server.py`：
```python
PUSH_TASKS = False   # 登录应答里不推任务
```
改为**客户端按需**（打开任务面板时其 C→S 1101/1103 请求→服务端应答）或调试期
用 UDP 控制通道 `tasks` 手动推送。

修复后实测：**PromptState NRE = 0，主城完整显示**。

## 3. 任务系统复活

### 契约（messages_full.json）
| msgid | 类型 | 字段 |
|---|---|---|
| S→C 1103 | `CCMsgRequestOnceTask_Ret` | `1: repeated COnceTaskInfo` |
| S→C 1101 | `CCMsgRequestDailyTask_Ret` | `1: repeated CDailyTaskInfo` |
| 元素 | `COnceTaskInfo` | `1: taskId(int32)`, `2: finishTimes(int32)`, `3: delete(bool)` |
| 元素 | `CDailyTaskInfo` | `1: taskId(int32)`, `2: finishTimes(int32)`, `3: isPrized(bool)` |

### 关键编码规则（本次修正）
`taskId` / `finishTimes` 的契约类型是 `raw:280008` = **int32，DataFormat=2 → 定长 fixed32 整数**。
此前用 `proto.f32_field`（float）编码 → value 位模式被当作 int 读 → **taskId 错值** → 列表空。

新增 `server/proto.py`：
```python
def i32_field(field, value):
    """DataFormat=2 的 int32 字段——必须定长整数，不是 float！"""
    if value == 0:
        return b""
    return tag(field, 5) + struct.pack("<i", int(value))
```
`build_task_info` 改用 `i32_field`。

> ⚠ 附注：契约里的 `dataFormat` 字段**并不可靠**（例如 102 的 `level`/`jinbi`
> 用 varint 编码反而工作）。可靠做法是看 `type` 的 raw 值区分真实 CLR 类型：
> `280008`=int32、`28000c`=float、`28000e`=string、`280002`=bool。

### 时序
推送后任务面板需**重新打开**（或面板打开时读取）才刷新出列表。

### 实测
任务列表完整显示：

## 4. 环境与工具链经验

1. **必须同时启动两个服务**（`server/start.bat` 的逻辑）：
   - 更新服 `update_server.py`（HTTP :80）—— 客户端启动时拉 Version.bytes / serverlist.txt
   - 游戏服 `game_server.py --port 9001 ...`（TCP :9001）
   只起游戏服 → 客户端初始化阶段显示"网络不给力"。
2. **进程存活**：`nohup` / `run_in_background` 的后台任务会随命令回合被回收；
   改用 PowerShell `Start-Process -PassThru` 分离进程可跨命令存活。
3. **宿主 IP 变化不致命**：本次宿主 IP 由 `192.168.0.12` 变为 `10.33.42.235`，
   但设备 hosts 里的 `192.168.0.12 game.360joy.com.cn` 仍有效（MuMu 内部映射），无需重注入。
4. **客户端崩溃排查**：`logcat` 里 `Zygote: Process exited due to signal 6 (Aborted)`
   + `houdini arm backtrace ... mono_compile_method` = houdini(ARM→x86) 转译下 Mono JIT
   的偶发崩溃，**随机、可重试通过**；内存充足（MemFree 4.9 GB）。
5. **DLL 补丁边界**：`patched6`（增加 Daily/TeQuan PromptState 补丁）会触发该 SIGABRT；
   `patched5`（仅 OnceTask 补丁）稳定 —— 暂以 patched5 作为基线。
6. **装包链路**：`repack_apk.py --dll <bin>` → `sign_apk.py <apk> --inplace` → `adb uninstall/install`。
